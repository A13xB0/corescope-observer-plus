    Guest key

    Off

    A guest identity used to poll a repeater, so any observer that hears the reply can feed CoreScope. The plugin makes a separate polling key for this (never the repeater's own key, which is never shared) and registers it with CoreScope, which decodes the replies others overhear and credits them here; on a CoreScope without that, the public shared key is used instead. CoreScope also picks one observer to poll each repeater, so others don't repeat the request. The Poll with the guest key setting under Polling sets the default; a repeater's Details can override it. The key only ever logs in blank or with "hello", never as admin.

    Polling

    Reach One-hop requests go direct through a relay you hear directly. Each costs the relay two transmissions.

    Every packet the plugin sends goes direct; nothing it sends is flooded. A repeater floods its answer only when it has no route back, so the plugin sends it one before asking.

    Publish to

    Brokers already set up in openHop. Companion-key readings (repeaters with a saved password) go out under this repeater's key on its own short connection; openHop's connection is not touched. Guest-key readings aren't published here: openHop uploads the repeater's reply like any packet it hears, and CoreScope decrypts it with the polling key, so they never show in Last publish.
